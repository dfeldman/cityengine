# Assets: what is generated, and how to get it back

The repo holds **code and small runtime assets**, and is kept under 100 MB. Everything large is generated by a
tool in this repo, so a fresh clone builds it rather than downloading it. This file is the list of what to run.

Two directories used to be committed and no longer are. They were **705 MB of the 772 MB** that was tracked:

| | was | what it is |
|---|---|---|
| `public/cities/` | 190 MB | the baked city packages and their streamed tiles |
| `docs/shots/` | 515 MB | every screenshot — model shots, contact sheets, reference photographs |

## The shared asset bucket (the default since 2026-10-13)

The models and textures that are **not** made by the bake now come from the shared asset bucket, so a fresh
clone needs none of steps 3 and 5 below to ride. `src/assets.ts` reads the assetmgr indexes over public HTTPS
(no key) and maps each path the game asks for to its file in the bucket:

| what | path the game asks for | index (owner) |
|---|---|---|
| trees, plants, rocks | `trees/`, `plants/`, `rocks/*.glb` and their `index.json` | `assetkit-trees`, `-plants`, `-rocks` (assetkit) |
| the Paris statues | `models/paris/*.glb` | `assetkit-statues-paris` (assetkit) |
| avatars | `mh/`, `env/` | `avatarkit-*` (avatarkit, through its `loadFromBucket`) |
| SF street trees, extruded signs | `sftrees/`, `models/signs/` | **`streetrunner`**: this repo's own, `indexes/asset-index-streetrunner.json` |

Everything else (palms, facades, roads, flags, landmarks, the rock surfaces, the city bake) is still read from
`public/`. `?assets=local` reads all of it from `public/` again, as before; the views tool takes `--assets=local`
for before-and-after sheets. The phone tier's texture caps match bucket files by the path they stand for, so
they apply exactly as they did.

After regenerating the street trees or the signs, record and upload them (assetmgr lives at
github.com/dfeldman/assetmgr, beside this repo by default or at `$ASSETMGR`):

    node --experimental-strip-types tools/assetmgr-import.ts
    ASSETMGR_ENV_FILE=~/assetmgr/.env npx --prefix ../assetmgr assetmgr upload

A rebuilt file gets a new name (its hash changed): the import adds it to the same asset and marks the old file
`isDeleted`, and `assetmgr delete --yes` later clears the old one from the bucket. Browse the bucket with
`~/assetmgr/viewer/index.html`.

## What a fresh clone needs, in order

**0. The sibling repos and the files kept out of git.** Check out `assetmgr`, `assetkit` and `avatarkit` beside
this repo (`npm install` in assetmgr builds its CLI), then put back the textures the game reads by fixed name
(facades, palms, roads, rock surfaces) from the shared asset bucket, public and keyless:

    npx --prefix ../assetmgr assetmgr restore     # or: node ../assetmgr/dist/cli.js restore


**1. The OSM extract** (needed by the bake; ~650 MB, cached, never committed)

    npm run osm:fetch

Downloads the Geofabrik extract for the region into `tools/cache/osm/`. Without it the bake falls back to
public Overpass instances, which are rate-limited to the point of being unusable for a city-sized box — see
`docs/OSM-DATA.md`. Needs `osmium` (`brew install osmium-tool`).

**2. The city packages** — this is the big one

    npm run bake san-francisco
    npm run bake paris-centre

Writes `public/cities/<city>.json` plus its `tiles/` and `ride-*.json`. **Nothing renders without this.** With
the local extract the OSM phase is a minute or two; the rest of the bake (terrain, facades, the ride graph,
plantings) is the bulk of the time. The bake also generates the city's signs (step 3) on its own.

**3. Sign lettering** (also run by the bake; `public/models/signs/`, and `public/models/` is ignored wholesale)

    npm run signs

Extruded letterforms in a real typeface, from `tools/signgen/signs.json`. See `tools/signgen/README.md`.

**4. Facade, palm and road textures** (`public/facades/*.png`, `public/palms/`, `public/roads/` — not in git)

Step 0 restores them from the bucket. To rebuild them from their generators instead:

    python3 tools/facadegen/paint.py

then record and upload the result with `node --experimental-strip-types tools/assetmgr-import.ts` and
`npx assetmgr upload`. (`public/facades/atlas.json` stays in git: it is the layout, not an image.)

**5. Tree and plant libraries** (`public/sftrees/`, the GLBs in `public/trees/`, `public/plants/` — not committed)

    python3 tools/sftrees/library.py

Blender-generated, from the species definitions in `tools/sftrees/species/`, with assetkit's treekit (the repo
beside this one, or `$ASSETKIT`). The index (`tools/sftrees/library.json`) is committed, so the list of what exists
survives even when the meshes do not. The game itself reads all of these from the bucket (src/assets.ts), so
this step is only for changing them; `public/trees` and `public/plants` are links into assetkit's generated
libraries, used only with `?assets=local`.

## What is NOT regenerable, and therefore must stay committed

- `public/landmarks/**` — the manifests. These are the record of every modelling decision made: which building
  gets which builder, which gets which facade style, the colours, the notes. **They are the work.**
- `src/**`, `tools/**`, `tests/**` — including every landmark builder.
- `docs/*.md`, `docs/sf-batches/**` — the briefs, the registers, the batch lists, the bail-out lists and the
  queue log. `docs/sf-buildings.csv` and `docs/sf-queue*.csv` are derived but cheap and worth having in the
  history, because they say what was done and when.
- Nothing binary. Every image and model is either in the shared asset bucket (index `streetrunner`, restored
  by step 0 or read by URL) or generated by a tool here. `incoming_models/` (Tripo statues in progress) is
  deliberately local and uncommitted: finished statues go to assetkit's statue indexes.

## Screenshots

`docs/shots/` is gone from git and stays on disk. Rebuild what you need:

    node --experimental-strip-types tools/model-sheet.ts            # contact sheet of every model
    node --experimental-strip-types tools/model-shots.ts --entry="…"  # one building, four angles
    npm run shots                                                   # the facade-style showcase, all 16

All three need the dev server running (`npm run dev`) — they drive it, they do not start it.

**Why they were dropped:** a screenshot is evidence for a decision made at a moment, and the decision itself is
in the manifest and the notes. Keeping half a gigabyte of PNGs to preserve the moment is the wrong trade — and
they were being regenerated constantly, so nearly all of that half-gigabyte was history nobody would read.

## Reference photographs

`statues_to_model/` (gathered for hand modelling; moved to assetkit on 2026-10-14, beside the statue work) and `docs/shots/refs/` (fetched for the refacing ladder) are
not committed. They are re-fetchable — `tools/sf-photos.ts` for the ladder's street-level views — and their
licences belong to Wikimedia and Mapillary, so the repo is not the right place to hold copies.

## The history

The history was rewritten on 2026-10-13 and 2026-10-14 (`git filter-repo`) to drop everything that is now
generated or in the bucket: `docs/shots/`, `public/cities/`, `incoming_models/`, and the images listed in
.gitignore. Backups of the repo before each rewrite are in `~/repo-backups-2026-10-14/` and
`~/streetrunner-git-backup-2026-10-13/` on the original machine.
